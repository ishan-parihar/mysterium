## 2. Findings — 7 bugs, 1 design gap

### CRITICAL — Curriculum cold-start was 100% broken for new players

* **A1 + persistence (root cause):** `seedInitialKnowledge('Cognitive','Red')` returned `size 0` because every concept's `stageRange.min` is `Amber` (3) while new players are `Red` (2). Filter `stageOrd >= minStageOrd` excluded all 7 concepts. **Fix:** widen to `stageOrd +1 === minStageOrd` (Red can study Amber as "next material", 0.7× priority). **File:** `src/core/curriculum/SeedInitialKnowledge.ts`.

* **Persistence (root cause of 0 after fix):** `Significator.knowledge` holds `Map`s (`conceptStates`, `subjectProgress`, `forgettingCurves`). `SaveRepository.saveGame`/`saveAll` did `JSON.stringify(sig)` — `Map`s serialize to `{}`. So even after seeding 4 concepts, `save.json` showed `{}` and `curriculum status` showed `0 concepts`. **Fix:** `serializeSignificator()` converts Maps to plain objects before stringify; `validateSignificator` already reconstructs. **Files:** `src/infra/persistence/SaveRepository.ts`, `scripts/cli-game.ts:createDefaultSignificator` backfill for pre-fix saves (0 → 4 on next load).

**Before:** `HOME=$TMP npx tsx scripts/cli-game.ts --headless --encounters 1 → save.json conceptStates 0 → curriculum status "0 concepts, asking for attention (0%)"`.

**After:** same command → `4 concepts, 90% retention` → `curriculum status` shows `4 rubrics (74% health), concepts studied: 4, avg retention: resting well (90%)`, `curriculum progress` shows 4 strongest.

### HIGH — `export --analytics` rejected by commander

* **B5:** `src/cli/ExportRuntime.ts` defined `--analytics`, but `scripts/cli-game.ts`'s commander `export` command omitted it → `error: unknown option '--analytics'`. **Fix:** add `.option('--analytics', …)` to commander. **After:** `mysterium export --format json --analytics` returns `{"learningAnalytics": {"studyEfficiency":[],"velocity":{…},"modalityEffectiveness":[],…}}` (0 velocity for seeded-only saves is correct — velocity needs `studyHistory`).

### HIGH — Telemetry opt-in and `events` were inert

* **A3 — opt-in unreachable:** docs say `~/.mysterium/config.json: {"telemetry": true}`, but `CLITelemetry.readOptIn` only checked KV key `mysterium:cli-telemetry-opt-in`. **Fix:** also read `config.json` (legacy dir). **File:** `src/cli/CLITelemetry.ts`.

* **A3 — `events` showed nothing after a session:** `runEvents` only read `collector.getEvents()` (in-memory, per-process). Each CLI invocation gets a fresh collector, so prior session's flushed events (in `TelemetryStore`) were invisible. **Fix:** `loadPersistedTelemetry()` reads `TelemetryStore.load()` (legacy dir, base64) and merges with buffered. **File:** `src/cli/CLITelemetry.ts`, `scripts/cli-game.ts:runEvents`.

* **A3 — flush never happened for DQ headless:** `runFullSession` does `await runDirectQuestioningSession(...); return;` before its `flushCLITelemetry`. DQ had no flush, so headless produced 0 file. **Fix:** DQ now flushes the shared collector (`buildCLITelemetry` → `flush`) so parent's `session_started` is persisted. **File:** `scripts/cli-game.ts:runDirectQuestioningSession`.

* **A3 — profile/legacy dir flip:** `FileKeyValueStore` defaultDir flips between `~/.mysterium` and `~/.mysterium/profiles/default` depending on `_active` symlink. `CLITelemetry` used defaultDir, so write went to legacy (no `_active` yet) but read went to profile (after `_active` created) → 0. **Fix:** `legacyKV()` always uses `path.join(os.homedir(), '.mysterium')`. **File:** `src/cli/CLITelemetry.ts` (also switched from `require('os')` in ESM to `import * as os`).

**Before:** `echo '{"telemetry":true}' > ~/.mysterium/config.json; mysterium --headless …; mysterium events` → `Telemetry is disabled` / `No events buffered`.

**After:** same → `Recent 2 of 2 event(s): session_started, encounter_started` and file at `~/.mysterium/mysterium:telemetry.json` (base64).

### MEDIUM — Recalibration never triggered for old saves

* **B6:** `GameLoop.startSession` checked `lastSessionAt` (new field) but never fell back to `theta.lastEncounter` as the comment claimed. Old saves have no `lastSessionAt` → recalibration never fired. **Fix:** fallback to `Math.max(...Object.values(theta.lastEncounter))`. **File:** `src/core/GameLoop.ts`.

### MEDIUM — Per-line transformation was dead code

* **B8:** `detectPerLineTransformation` was exported but never called. Phase B claimed "supplements single global currentStage" but `GameLoop` never used it. **Fix:** `startSession` computes `perLineTransformations` for `nextStage` and stores in `SessionState`; `tickWithStrategy` refreshes it each tick. **File:** `src/core/GameLoop.ts` (also added `perLineTransformations` to `SessionState`).

### LOW — Duplicate telemetry session event

* DQ + FullSession both emitted `session_started`; with shared collector this duplicated. **Fix:** DQ no longer emits `session_started`/`session_ended`; it relies on FullSession's events and only flushes. Verified file now has 2 events (not 3).

### Design gap (not a bug) — Curriculum beats only in FullSession

* `--curriculum` and `tickWithStrategy` curriculum beats are wired, but `runDirectQuestioningSession` (8-line DQ) is a separate loop that never calls `tickWithStrategy`. So `mysterium --headless --curriculum --encounters 5` still shows 5 DQ questions, no `curriculumConceptId` label, and `studyHistory` stays 0. This is by design (DQ is 8 lines, not GameLoop), but worth noting for future `--curriculum` headless.
