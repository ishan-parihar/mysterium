## 1. Executive summary

**As-built is plan-faithful on the kernel, adaptive, telemetry, and CLI surfaces (G2–G5, G7, G9–G11). The agentic surface (G1/G6) is correctly implemented at the per-encounter tool boundary but not at the session level where the plan intended it to live.** Concretely:

- The five training tools are registered, budget-enforced, Veil-safe, and tested via real `BrainGameEngine` loops — an LLM *can* run games mid-encounter when the caller supplies a `TrainingIntegration`. No tool-sprawl, no timing compromise, no Veil leak.
- Free and guided workouts, `insights --days/sparkline`, `--practice/--window/--accessible`, pipe-safe + JSON event streams, and `export json|csv` all ship and persist to `TrialRecordStore`/`CognitiveIndex`/`CalibrationStore`.
- **The session-level workout composition described in `03 §4.2` and `05 D1/D4` (“`GameLoop.tickWithStrategy` dispatches `workout` slots alongside narrative encounters, bridging `AutoModeStrategy` bias”) is absent.** `GameLoop.ts:52-572` schedules only narrative/curriculum/shadow/threshold encounters; `WorkoutPlanner` is invoked only from `TrainingRuntime.runTrainCommand` as a standalone CLI flow, never from `GameLoop` or `AutoModeStrategy`. Consequently training beats are **CLI-invoked workouts**, not **agent-orchestrated beats inside a narrative session** — the upgrade's headline integration (“the agent frames a workout inside a session”) is achievable per-encounter but not yet woven into the session arc that players actually play.
- No other plan blocker. All other gaps are **polish/extension**, not architecture violations.

**Gates at audit time:** `workspace-lint 0/0/0` · `npx tsc --noEmit` 0 errors · `npm run build` invariants + svelte sync + tsc + vite + adapter-cloudflare green · `aft_inspect` diagnostics 0/0/0 · `~700+` tests green across batched suites (see §5). ## 3. Infrastructure integration audit

### 3.1 Hexagonal discipline — **pass**

All new logic is pure `core/` (`braingame`, `adaptive`, `training`) → persistence through `KeyValueStore` port → terminal via `CliGameUi` adapter. `BuildTrainingIntegration` is the only composition root (`TrainingRuntime.services()` singleton over `FileKeyValueStore` → `CalibrationStore`/`TrialRecordStore`/`CognitiveIndex`). No `core` import of `infra` except via port. `06 §1` module map is accurate (`file:line` verified).

Deviation: `FileKeyValueStore` lives in `src/infra/persistence/` as planned; its `defaultDir()` resolves via `~/.mysterium` or `_active` symlink (`FileKeyValueStore.ts:11-22`) — matches `SaveRepository` posture. No `NodeKeyValueStore` rename.

### 3.2 Agentic loop — **tool surface shipped, session composition missing**

**What works:** `AgenticOrchestrator` integration is exemplar. `constructor({training?})` optional (`AgenticOrchestrator.ts:247`) leaves legacy callers (WebUI `routes/`, `scripts/cli-game.ts` session path) byte-identical when omitted; `toolsForRun()` (`:268-270`) appends `TRAINING_TOOLS` only when present; `trainingContext()` + `handleTrainingTool` (`trainingTools.ts:196-290`) centralize `appendSession`, `recordGame`, calibration EMA, `persistIndex`, `fatigue` verdict, `workout.progress`; system prompt `TRAINING_RULES_SUFFIX` (`trainingTools.ts:147-151`) is concatenated at `AgenticOrchestrator.ts:435`; budget forcing mirrors `ask-budget` (after `N run_brain_game` matching `plan.length`, inject forcing `complete_workout`); unknown tool names degrade gracefully (`ok:false`).

**Where it is *not* intuitive/efficacious yet:**

1. **Session-level composition absent.** The plan's keystone — `03 §4.2` / `05 D4` / `21 Incarnation Architecture` session that may contain `workout` slots alongside narrative encounters, with `GameLoop.tickWithStrategy` dispatching either kind and `AutoModeStrategy` biasing workouts toward decaying lines — is not implemented. Today a player either runs a **narrative session** (`mysterium`/`mysterium session --encounters …`) with *zero* brain games, or a **standalone workout** (`mysterium train …`) with *zero* narrative framing. The two never compose. An LLM *could* interleave them if the caller constructed a `TrainingIntegration` with a `workout` plan and passed it into a single `AgenticOrchestrator` encounter, but `GameLoop` never does so; `TrainingRuntime.buildTrainingIntegration()` is wired only for CLI free/guided paths, not for `startSession/tickWithStrategy`. `src/core/GameLoop.ts` has zero `workout`/`paradigm`/`CognitiveIndex` refs; `src/core/engines/AutoModeStrategy.ts` has zero `WorkoutPlanner` refs.

2. **No GameLoop↔CognitiveIndex feedback.** `CognitiveIndex.applyDecay()` is called on `train`/`insights` CLI invocations, not on `startSession`/`tickWithStrategy`. A player who only does narrative sessions sees no skill decay; a player who only trains sees no `CCIEngine`/`polarity`/`greatWay` integration. The `CognitiveIndex` and `Significator`/`CCI`/`rayProfile`/`metabolicHealth` are parallel universes (`CognitiveIndex.ts:15-138` vs `CCIEngine.ts` 36 symbols) with no `toSnapshot` bridge.

3. **WebUI parity deferred by design** (`05 out-of-scope`) — `src/routes/` renders narrative encounters only; no training surfaces. `AgenticOrchestrator`'s `training?` opt-in is CLI-only. Acceptable per canon, but the next full-scale plan must decide whether `CognitiveIndex`/`TrialRecordStore` belong in the BFF (`src/routes/api/`) or remain CLI-local.

4. **Timing integrity vs agentic granularity tradeoff is correctly biased (03 §1: timing integrity wins),** but the current cost is that `run_brain_game` is a *synchronous native execution* inside the tool call (seconds), blocking the LLM loop. This is the right tradeoff for `reaction_time`/`go_no_go`, but it means `recommend_workout` → `ask_user_question` (consent) → `run_brain_game` must happen sequentially in the LLM's turn loop — `AgenticOrchestrator.run:374-608` handles this by streaming tool calls for up to 10 iterations, which is sufficient, but the 10-iteration `maxLoops` budget could be tight for a 6-item workout (6 `run_brain_game` + 2 framing + `complete_workout`) if `recommend_workout`/`get_training_profile` are also used.

### 3.3 CLI — **polished, pipe-safe, testable**

Commander declarations in `scripts/cli-game.ts:144-157` now declare `train` (`--free/--trials/--difficulty/--minutes/--focus/--plan/--demo/--practice/--window/--accessible/`), `insights` (`--days/--json`), `export` (`--format/--paradigm/--days/--out`); dispatch at `scripts/cli-game.ts:4889-4892` via `NON_INTERACTIVE_SUBCOMMANDS` + `runTrainCommand(runArgs, JSON_MODE)`/`runInsightsCommand(dev, runArgs, JSON_MODE)`/`runExportCommand`. `BrainGameCli.runInteractiveGame` (`BrainGameCli.ts:274-360`) correctly builds a single `BrainGameEngine` with a wrapped `sink` that both persists and emits `game_trial` JSON, plus `game_start`/`game_summary` events; header/insight rendering checks `jsonEvents || !isTTY` → `renderBarPlain`/`plain` strings, so `… | cat` and `… --json` are pipe-safe.

Training persistence post-Phase E fix (audit caught the prior gap): `TrainingRuntime.runTrainCommand:131-168,208-236` now persists `TrialRecordStore.appendSession` + calibration EMA + `index.recordGame` for both free and guided paths (previously only the agentic `handleTrainingTool` path persisted; CLI `train --free` was a raw demo). Verified: `HOME=/tmp/... train --free stroop --demo 1` now yields `trials:v1:data:stroop.json` (2 trials) and `insights --days 7` shows 1 session.

### 3.4 Persistence — **local-first, bounded, Veil-safe**

`FileKeyValueStore.ts:26-70` file-per-key (`*.json`) under `~/.mysterium` or `_active` symlink, atomic `tmp→rename`, `SAFE_KEY` regex, `get/set/remove/clear`. `TrialRecordStore:38-70` serializes `bigint latencyNs → string`, validates on `deserializeTrial`, caps `MAX_TRIALS 400`/`MAX_SESSIONS 100` via `slice`; `CognitiveIndex` shims missing lines on `load`. No `TelemetryStore` encryption reuse — acceptable, but note: trial records are **plaintext JSON** on disk (unlike `TelemetryStore`'s encrypted blobs). Canon privacy posture (`infra/telemetry/TelemetryStore.ts`) would want at least an opt-in encryption pass (see §6).

### 3.5 Veil & canon — **compliant with one watch item**

All player surfaces render felt-sense: `BrainGameEngine.feltSense` (`BrainGameEngine.ts:196-203`, 5 bands), `CognitiveIndex.feltSenseFor` (`CognitiveIndex.ts:126-133`, rising/decaying/stable × score), bars are `◆/◇` or `[=====     ]` plain, no `%`/`ms`/`z` on normal path. Raw numbers only behind `--dev` (`insights --dev` appends `(0.42, 3.1d)`) or `--json` (machine seam). `handleTrainingTool` enforces Veil in tool descriptions (“never expose numbers”). Trial loop never interleaves LLM (`BrainGameEngine.run` pure). Watch item: `export --format csv|json` exports raw `accuracy`/`latencyMs`/`paramsHash` — explicitly local-only opt-in per `05 E4`, acceptable, but the command should warn if run without an explicit `--out` that the file will be piped to stdout (current does not).

## 4. Intuitiveness & efficacy in the active agentic loop

**Happy path today (works):** `mysterium train` (or `train --free <id> --practice --accessible --window MS`) → demo-seeded or interactive trials → `insights --days 7` shows `↗/↘/·` bars + `▁▂▃` sparkline + felt-sense phrases → `export --format csv --out file`. The felt-sense loop is intact and additive (growth, not dopamine). CLI `--help` is discoverable: `mysterium --help` → `mysterium train --help` → `mysterium insights --help` → `mysterium export --help`.

**Where it is not yet intuitive/efficacious inside a narrative session:**

- A player in a 20-encounter narrative session never sees a training beat unless they *exit* and re-enter via `train`. There is no “the world grew quiet; a remembering exercise arises” moment where the Game Master *offers* a 2-minute workout *inside* the encounter fiction — that requires the missing `GameLoop`↔`WorkoutPlanner` composition. The agentic tools *can* do it per-encounter, but the session *does not afford* it.

- Difficulty feels static across sessions to a non-technical player. `AdaptiveDifficultyService` adapts within `BrainGameEngine` loops only when `adjustDifficulty` is wired, but `TrainingRuntime` guided/free paths **do not wire it** — they resolve `resolveStartLevel` once at game start (`CalibrationStore` EMA) and pass static `params` for the whole game. The plan's “staircase within a game” (`BrainGameEngine` `adjustDifficulty` hook at `BrainGameEngine.ts:51,136-145`) is implemented in the engine but **never connected** to `AdaptiveDifficultyService.createTrialAdjuster`. The `run_brain_game` handler (`trainingTools.ts:216-291`) likewise resolves `start.level` once and runs the game without per-trial adaptation. Players converge to bands only across sessions, not within.

- Fatigue is measured (`FatigueMonitor:93-126` `accuracy<0.45` + `RT>1.3×`) and `run_brain_game` returns `fatigueAdvice`, but the CLI guided path still prints a generic “Rest now. The exercises will keep.” and breaks — it does not surface the Veil-safe hint or swap to lighter (`FatigueMonitor 'lighter'` is never acted on; no `swap-to-lighter` logic).

- Calibration warming is invisible. `resolveStartLevel:169-182` does stale decay (`-0.02/d`) and `override` (direction `-0.12/+0.12` or absolute `level`), but there is no first-exposure calibration block (05 B4 wide→narrow). A fresh player starts at `0.35` neutral for every paradigm.

## 7. Full-scale, full-scope integration plan (next traversals)

The current as-built is a **CLI-complete training kernel** that is ready to be *composed* into the session fabric. The next plan should not add more paradigms or rendering; it should make the kernel **intuitively present inside narrative sessions and efficaciously tied to development**.

### Stage 1 — Session composition (closes the headline gap; 1 traversal)

1. **Workout-slot type + `GameLoop` dispatch** — Add `EncounterKind = 'narrative' | 'training_beat'` (or a `WorkoutEncounterSpec`) to `src/core/domain/EncounterSpecNew.ts`; introduce `WorkoutPlanner` call inside `GameLoop.startSession`/`tickWithStrategy` (guarded by a strategy flag `strategy.trainingSlots?: number`). The `EncounterScheduler.scheduleNext()` (or a new `TrainingSlotScheduler`) selects `paradigmId` from `CognitiveIndex` decay + `AutoModeStrategy` bias; `tickWithStrategy` returns a `TickResult` that is either a narrative encounter (current path) or a training beat that the CLI/WebUI renders as a framed game. Reuse `06 §5` wiring: `resolveStartLevel` → `BrainGameEngine` → `appendSession`/`recordGame`/`calibration.put` + `FatigueMonitor` inside the loop. Acceptance: `mysterium session --encounters 5` can now include `2` training beats intertwined with narrative, all persisted, `insights` reflects both.

2. **`AutoModeStrategy ↔ WorkoutPlanner` bridge** — Thread `strategy.weightBias` and `sessionContext` through `planWorkout` (today `focusLine`/`excludeLines` only). The strategy's `weightBias` already encodes line/stage bids; map it to `PlanOptions.focusLine`/`excludeLines` so workouts align with the session arc rather than fighting it (`03 §3.6`).

3. **Integration seam test** — `tests/core/assessments/AgenticOrchestrator.training.test.ts` (new): construct a `TrainingIntegration` with `InMemory KV` + seeded `GameRunnerPort` (`demo` 0.7), drive `AgenticOrchestrator` with a 3-item `WorkoutPlan` via a fake `queryLLMWithTools` that sequentially calls `run_brain_game` → `complete_workout`; assert `TrialRecordStore.recentSessions.length === 3`, `CognitiveIndex.snapshot()` decay-aware, `CalibrationStore` EMA updated, Veil strings contain zero `%`/`ms`.

### Stage 2 — Efficacy (make training *training*; 1 traversal)

4. **Wire per-trial staircase** — In both `TrainingRuntime` (CLI) and `handleTrainingTool` (agentic), replace once-per-game `resolveStartLevel` with `createTrialAdjuster(paradigm, initAdaptiveState(start.level), strategy)` and pass `adjustDifficulty` into `BrainGameEngine` (`BrainGameEngine.ts:51`). Strategy selection: `go_no_go`/`reaction_time` → `composite_accuracy_rt`, others `weighted_up_down`. Acceptance: synthetic-user simulation `tests/adaptive/SyntheticConvergence.test.ts` (new) drives 100 trials per strong/weak/noisy player and asserts distinct stable bands within 2 sessions.

5. **First-exposure calibration block** — When `CalibrationStore.get(paradigmId) === null`, run a 6-trial wide-exploration block (`windowMs` long, no `CognitiveIndex` credit) before the scored block; persist `baselineLevel`. Optionally re-expose as `mysterium calibrate [--paradigm] --wide` (the deferred `05 B4`).

6. **Fatigue swap + `CognitiveIndex` bridge to `GameLoop`/`CCI`** — On `FatigueMonitor` `lighter`, swap remaining `WorkoutPlan` items via `planWorkout(..., excludeLines: fatiguedLines)` rather than `break`; call `CognitiveIndex.applyDecay()` inside `GameLoop.startSession` (or on `tick` once per session) so narrative-only sessions still decay skills; optionally expose `CognitiveIndex.snapshot()` to `toSnapshot` Veil prose (`narrative-memory.md`).

### Stage 3 — Hardening & WebUI decision (1 traversal)

7. **Encrypt trial store (opt-in)** — Wrap `TrialRecordStore` via `KeyValueStore` encryption (reuse `infra/crypto/` pattern from `TelemetryStore`) gated by `AccessibilitySettings.telemetryOptIn` or a new `trainingOptIn` flag. Add a migration that re-encrypts existing `trials:v1:*` on first `export` if needed.

8. **Decide WebUI parity** — If training stays CLI-local, keep `TrialRecordStore` in `FileKeyValueStore` and expose `GET /api/training/insights` as a read-only BFF proxy over the same store (requires WebUI file access). If training moves cloud-synced, promote `TrialRecordStore` to `SaveRepository`-like versioned document and sync via `Cloudflare KV` (already `api/save` encrypted-blob). Either way, add `src/routes/(app)/training` SvelteKit surface that reuses `CognitiveIndex.feltSenseFor` + `renderSparkline` (SSR-safe).
