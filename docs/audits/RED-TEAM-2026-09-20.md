# Red-Team Audit — documentation infrastructure & development workflow

> **Date:** 2026-09-20 · **Scope:** the tooling that manages, ingests, and retrieves the
> documentation knowledge-base, and the workflow that keeps canon, code, and records aligned.
> **Method:** every claim below was executed against the working tree on this date
> (`scripts/arch.py`, `_org.yaml`, `docs/`, `src/`, `scripts/`, `.github/workflows/`).
> **Status:** evidence for the RG ledger. Not an authority — `docs/system/AGENTS.md` and
> `docs/foundations/AGENTS.md` own the contracts this audit measures against.

---

## 0. Verdict

The question was: *do we have in-house utilities to manage and ingest the whole documentation
KB, so future agents can align, audit, and refactor from the foundation docs?*

**Three capabilities are needed. One exists, one is broken, one is absent.**

| Capability | What it means | State |
|---|---|---|
| **MANAGE** | declare structure, author records, validate the doc set | ✅ **exists and is strong** |
| **INGEST** | turn docs into something code/agents can consume deterministically | ⚠️ **one path, stale + orphaned** |
| **RETRIEVE** | answer "which docs govern this code, and what do they require?" | ❌ **absent** |

The transmutation built a real *authoring and validation* layer. It did not build a *consumption*
layer. An agent can now be told the rules and can be caught breaking them; it still cannot ask the
repository what a given module is supposed to do.

## 2. Findings

Severity: **S1** = the stated objective cannot be met until fixed · **S2** = a promised mechanism is
decorative or silently wrong · **S3** = will bite on the next routine change.

---

### RT-1 · S1 — there is no retrieval surface; `route` cannot answer the question an agent has

`arch.py route` is the advertised entry point (`AGENTS.md §2.0`). It resolves *documentation* paths
to a rung. It does not resolve **code**:

```
$ python3 scripts/arch.py route src/core/assessments
rung:   (unclaimed)
mysterium: this path is not declared in _org.yaml
```

`cmd_route` has an organ branch, but it matches only `docs/system/sub-systems/<organ>/`. The
`code:` arrays declared on every organ in `_org.yaml` — the actual mapping between a code domain
and its contract docs — are **never read for routing**. No reverse index exists anywhere in the
repository (no code→contract lookup, no annotation convention, no `arch show`).

**Consequence.** An agent asked to change `src/core/orchestration/` has no deterministic way to
learn that `foundations/43` governs it. Alignment with the foundation docs is therefore manual,
per-agent, and unreliable — which is exactly the failure the governance layer was built to prevent.

**Direction.** `route` should resolve **both directions**: a doc path → rung/organ/records, and a
code path → organ + its `contract_docs` + the organ's AD/RG. A `context <path>` verb should emit
the bundle an agent needs to start work (contract docs, invariants, open RGs).

### RT-2 · S1 — the only doc→code ingester is stale, orphaned, and fails silently

`scripts/build-concept-index.ts` is the single bridge that turns the 512-file corpus into data the
runtime consumes. Three defects, each verified:

1. **Stale constants.** It hardcodes `STAGES = [..., '07-turquoise', '08-white']`. Those directories
   were renamed to `07-teal` / `08-turquoise` in P1. The script uses `existsSync`, so it does **not**
   crash — it emits 64 modules with **empty `modalities` arrays** and default titles. A silent
   degradation, not an error.
2. **Orphaned.** It appears in no `package.json` script and in no CI job. Nothing runs it, and
   nothing runs a check that its output matches the corpus.
3. **The output is already drifted, and it reaches the validation kernel.**
   `src/core/data/concept-drafts.json` (last written 2025-07-05) still carries
   `stage: "Turquoise"` and `stage: "White"`. It is imported at
   `src/core/validation/gates.ts:38` and consumed at `:599`.

**Consequence.** Canon says Teal/Turquoise; the code-side corpus index says Turquoise/White; the
generator that would reconcile them is broken and unrun. This is `MY-RG-0005` (canon↔code drift)
materialising in the ingest path itself.

**Direction.** Fix the constants; wire the generator into `build` **and** add a reconciliation check
so the JSON cannot silently diverge from the corpus. The `stage` values flip together with
CODE-PASS (RT-9) — the JSON is currently *correct for the code as it stands*.

### RT-3 · S1 — 8 of 10 gates inspect only 23 records; **595 governed documents have no integrity check**, and the root canon docs have none at all

Gate coverage, verified by reading `scripts/arch.py`:

| Gate | Iterates | Files inspected |
|---|---|---|
| DG1 frontmatter · DG2 status · DG3 numbering · DG8 references · DG9 ledger · DG10 canon↔code | `records()` | **23** |
| DG4 authority · DG5 vocabulary · DG6 quarantine | `live_files()` | **634** |
| DG7 ownership | owners table + foundations | 52 owners / 46 files |

There is **no gate over document content**: no link integrity for canon, no contradiction or
duplication detection, no "every foundation's terms are defined in `44`" check. DG8 — the link gate —
checks markdown `](....md)` links *inside records only*. Live canon uses **wiki-links** instead: 145
`[[…]]` occurrences, and **0** markdown `.md` links. (All 145 currently resolve — nothing keeps
them that way.)

**Worse — six files sit outside every rung.** `live_files()` is derived from the rungs, and these are
in none of them:

```
docs/00-vision.md               docs/02-glossary.md
docs/01-first-principles.md     docs/03-research-methodology.md
docs/INDEX.md                   docs/CHANGELOG.md
```

```
$ python3 scripts/arch.py route docs/00-vision.md
rung:   (unclaimed)
```

So **the vision, the first principles, and the glossary are governed by no gate and resolve to no
rung** — while `AGENTS.md §2` presents them as part of the set. These are the first documents a new
agent reads.

### RT-4 · S2 — no gate over generated surfaces; `docs/INDEX.md` was committed stale

`docs/INDEX.md` as committed declared:

```
## Records (0)
| historical | `docs/historical` | no | `—` |
```

Both wrong: 23 records existed, and `_org.yaml` names `docs/historical/AGENTS.md` as the authority.
Re-running `python3 scripts/arch.py emit` produced the correct 23-row table and the correct
authority. Nothing detected the mismatch, because **`INDEX.md` is in no rung** (RT-3) and no gate
compares a derived file against its regeneration.

**Consequence.** The repository's own index — the first artifact an agent opens after `AGENTS.md` —
lied about its contents and the lie was committed. Any generated surface (`INDEX.md`, 13 organ
routers, the corpus JSON) can silently drift the same way.

### RT-5 · S2 — the governance CLI's own controls are partly dead code, and the CLI is untested

**5a — gate enable/disable flags do nothing.** `Gate.run()` looks up
`cfg["gates"][f"{name.lower()}_{name.lower()}"]`, i.e. `dg1_dg1`. The real keys are
`dg1_frontmatter`, `dg2_status_enum`, … Every lookup returns `None`, so the default (`enabled: True`)
always wins:

```
$ python3 -c "...cfg['gates'].get('dg1_dg1')..."
what run() looks up for DG1: None
=> enabled:false is silently ignored: True
```

Setting `enabled: false` in `_org.yaml` therefore has no effect — a fail-*open* surprise in the one
component whose job is failing closed.

**5b — DG3's reuse check is unimplemented.** `dg3_numbering` builds `retired: set[str]` from the
ledger and then **never reads it**. Number re-issue (`case` reuse across a supersede) is declared in
the gate's docstring and not enforced. (Uniqueness *within* the live set is enforced; reuse *after*
retirement is not.)

**5c — the CLI has no test.** `grep -rln "arch.py\|_org.yaml" tests/` returns nothing. Gate efficacy
was demonstrated once by hand in P7 (three injected violations, each detected, then reverted) — a
one-off, unreproducible proof. `MY-RG-0010` ("a gate passes because its fixture cannot fail") is
recorded as a guard, but **the guard has no fixture of its own**.

### RT-6 · S1 — governance cannot fail anywhere it would be noticed (CI does not run it)

`.github/workflows/ci.yml`:

```yaml
on:
  push:
    tags: ['v*']
  workflow_dispatch:
```

CI runs on **tags and manual dispatch only** — not on push to `main`, not on pull requests. And its
step list is `svelte-kit sync → tsc → check:invariants → vitest → build`. It never runs
`workspace-lint` and never runs `arch.py validate`.

**Consequence.** The entire iteration protocol (`AGENTS.md §7.5`: workspace-lint → `arch.py validate`
→ build+test) is honour-system. A commit that breaks DG4/DG5/DG6, or that leaves `docs/INDEX.md`
stale, lands silently. The `_org.yaml → pending.DG-ENFORCE` item is confirmed accurate.

### RT-7 · S3 — organ record homes exist on disk but are not in git, and `Organ:` is never checked against its directory

`docs/system/sub-systems/*/core/{decisions,regressions}` — 13 organs × 2 dirs — are declared
mandatory by `_org.yaml` (`organ_pattern`). They exist locally and contain **0 tracked files**
(`git ls-files docs/system/sub-systems/kernel/core/` → empty). On a fresh clone they vanish.

Related: no gate compares a record's `Organ:` frontmatter to the directory it lives in, so
`_org.yaml`'s rule *"system-wide verdicts MUST NOT be filed in an organ core"* is unenforced. All 23
records currently live in the system core (correct), which means **the organ-scoped path has never
been exercised** — the first `arch.py new --organ X` would be the first test of it.

### RT-8 · S2 — the root router's map of the repository is pre-transmutation

`AGENTS.md §2.1` (the tree an agent reads first) still shows:

- `├── AGENTS.md   ← doc-tree router` — **`docs/AGENTS.md` does not exist**
- `├── archive/    ← Archived documents` — **moved to `docs/historical/`**
- `INDEX.md` listed under the nonexistent `docs/AGENTS.md`
- **no** `docs/system/` (rung 2+3), **no** `docs/historical/`, **no** `docs/audits/`, **no**

§2.2's uniqueness table also predates the transmutation (it does not carry `44`, and its
"Architecture / process docs" rows are partly rewritten elsewhere). The root router is the one file

### RT-9 · S1 — the CODE-PASS is the largest live canon↔code drift, and no gate can see it

Docs read Teal ↔ Turquoise. Code reads Turquoise ↔ White, in **67 files**: the `Stage` union and
`ALL_STAGES` (`src/core/domain/Stage.ts`), 8 assessment modules (`src/core/assessments/*/white.ts`),
threshold/altitude maps, `TaskRenderer` keys, glossary data, plus the corpus JSON (RT-2). Six
`CODE-PASS PENDING` annotations and ~39 held doc lines mark the frontier.

`MY-RG-0005` records the class; `MY-RG-0002` (vocabulary drift) can only inspect **documents**.
Nothing in the toolchain can detect that `Stage.ts` and `06 §5.1` disagree — and after RT-2 is fixed,
nothing will keep the corpus JSON and the corpus directories agreeing either.

---

### RT-10 · S2 — the vocabulary firewall detects phrasings, not senses

DG5 is regex-based against **6 blacklist entries** (`White`, `Turquoise`, `harvest`, `density`,
`Orange (as a density floor)`, `ATB`), each with a handful of patterns and a broad `exempt_in` list.
DG4 likewise matches 4 literal phrases (`binding architectural contract`, `is the single source of
truth for`, …).

A drifting document passes simply by wording it differently (`"the terminal stage"`, `"the summit of
the ladder"`, `"climb toward union"`). The gate is a **tripwire for known phrasings**, not an
enforcement of the senses — which is fine as a tripwire, but `AGENTS.md §7.5` presents DG5 as
"superseded vocabulary" being enforced, which overstates it. The semantic half rests entirely on the
AD/RG layer and on human review.

### RT-11 · S3 — housekeeping with teeth

- `.agents/` is untracked **and not in `.gitignore`** (skill installs write here, per platform
  instructions). An agent following the protocol but using `git add .` would commit it.
- Three files still contain `08-white` / `07-turquoise`: the generator (RT-2), the one-way migration
  script (intentional — it is the mapping), and its stale `.pyc`.
- `scripts/doc-path-reindex.py` is the **only record of the P3 path mapping** and is receipt-guarded
  (it refuses a second run). Two one-way scripts now encode migrations whose correctness is not
  independently verifiable from the tree.

Grouped by dependency, not by severity.

### Tier 2 — make the guards actually guard

| # | Action | Fixes |

| 11 | add a rung covering the 6 root docs (or move them under an existing rung) so DG4/DG5/DG6/DG7 see them | RT-3, RT-4 |

### Tier 3 — structural debt

| # | Action | Fixes |
|---|---|---|
| 13 | `.gitkeep` the 13 organ `core/{decisions,regressions}` dirs | RT-7 |

errors. The gap is that the docs are **writable and checkable but not yet readable-as-a-map**.
